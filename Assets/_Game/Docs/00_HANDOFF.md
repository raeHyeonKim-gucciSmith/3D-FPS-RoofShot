## 1. 가장 중요한 원칙 — 씬은 소모품, 생성기가 원본

`Assets/_Game/Scenes/Office.unity` 와 `Mission1~3.unity` 는 **매번 통째로 재생성**됩니다.
**씬을 손으로 편집하면 다음 빌드에서 전부 날아갑니다.**

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 캐릭터 배역, 임포트 보정, 히트박스, 무기 크기 | `Assets/_Game/CastingConfig.asset` |
| 계약별 거리·고도·탄수·경호원 수·타이머·**베뉴**·브리핑 문구 | `Assets/_Game/MissionSet.asset` |
| 맵 지오메트리 (옥상 크기, 엄폐물, 스카이라인, 표적 베뉴) | `Editor/RC_MapBuilder.cs` |
| 사무실 (방, 책상, 핀보드, 사진 부스) | `Editor/RC_OfficeBuilder.cs` |
| 게임플레이 기본값 (반동, 탄속, AI 수치) | 각 스크립트의 필드 기본값 |

> `MissionSet.asset` 에는 `assetVersion` 이 있습니다. `MissionSet.CurrentVersion` 보다 낮으면
> 생성기가 계약 정의를 `BuildDefaults()` 로 **다시 씁니다** (타겟 캐스팅만 보존). 새 필드가 추가됐을 때
> 옛 에셋이 "전부 옥상 테라스"라고 조용히 거짓말하는 걸 막기 위한 것이니, 인스펙터에서 손으로 수치를
> 튜닝했다면 **`BuildDefaults()` 쪽에도 반영**해 두세요.

## 2. 빌드 — 버튼 하나

> # `Rooftop Contract` ▸ **★ BUILD EVERYTHING** → Play
>
> 끝입니다. 다른 건 알 필요 없습니다.

이 하나가 아래를 순서대로 다 합니다:

1. 머티리얼 **URP 변환** (안 하면 헬기가 마젠타)
2. **팔레트 텍스처 수정** (안 하면 250m 캐릭터가 단색 덩어리)
3. **비어 있는 배역만** 자동 배정 (손으로 지정한 배역은 절대 안 건드림)
4. **사무실 + 미션 3개 씬 생성 + NavMesh 베이크**, 끝나면 **Office 씬을 열어 줌**

1·2 는 **이미 처리된 건 건너뜁니다.** 그래서 매번 돌려도 폴더 스캔 값만 듭니다 —
이게 사람 머리가 아니라 빌드 안에 들어갈 수 있는 이유입니다.

> 예전에는 `1` → `6` → `3` 을, 캐릭터를 추가했으면 `0b` 까지 순서대로 눌러야 했습니다.
> 그건 누르는 사람이 내리는 판단이 아니라 **도구가 알면서 안 하고 있던 의존 순서**였습니다.
> 이제 도구가 합니다.

### 나머지 메뉴 (한 단계만 따로 돌려야 할 때)

> **메뉴는 번호가 아니라 한글 이름입니다.** 예전 `0 / 0b / 1 / 2 / 3 … 9` 번호 체계는
> 폐기됐습니다. 자주 쓰는 3개만 최상단에 있고 나머지는 전부 `도구/` 아래에 대상별로 묶여 있습니다.
> 아래 `(옛 N)` 은 예전 문서·커밋 메시지를 읽을 때를 위한 대조표입니다.

```

  계약 설정 (MissionSet)                   계약 3개 수치 열기
  캐스팅 설정 (CastingConfig)              배역·히트박스·그립 열기
  계약 보드 초기화 (테스트용)               표적 3명 전부 부활

    캐릭터 — 히트박스 미리보기              눈으로 확인                    (옛 4)
```

**워크벤치가 무기마다 따로인 이유**: `SMG_P` · `AR_U` · `Pistol_I` · `Pistol_H` · `Pistol_J` 는
형상이 전부 달라서 같은 그립 값이나 왼손 IK 캡처값을 **공유할 수 없습니다**. 하나로 합치면
한 무기를 맞출 때마다 다른 무기가 어긋납니다. 저장 위치도 `CastingConfig` 안에서 각각 분리돼 있습니다
(`weapon*` / `pistol*` / `protectorPistol*` / `assaultPrimary*`).

**`씬 — 메커니즘 필드만 채우기`** — 재생성 없이 **기존 미션 씬을 현재 어셈블리로 다시 직렬화**합니다.
씬 파일이 옛 어셈블리로 구워지면 그 뒤에 추가된 public 필드가 **아예 직렬화되지 않고**, 로드 시
C# 기본값으로 들어옵니다 (`escortWhileCalm` 이 조용히 false 가 되는 식). 원인을 알고 급할 때만
쓰는 응급 도구이고, **정답은 언제나 ★ 재생성**입니다.

**`무기 — 플레이어 소총 배치 저장`** — 저격총은 이제 **계약마다 위치가 다릅니다**
(`MissionDefinition.playerRifleLocalPosition / playerRifleLocalEuler`). 미션 씬에서 `Rifle` 을
눈으로 맞춘 뒤 이 메뉴를 누르면 **그 미션의** MissionSet 항목에 저장됩니다. 계약마다 부감각과
난간 관계가 달라서 하나의 값으로는 세 계약이 다 맞지 않습니다.

**캐릭터를 새로 추가했을 때만** `캐릭터 — 리그 Humanoid 변환` 을 먼저 돌리고 ★ 를 누르세요.
FBX 를 전부 재임포트해서 느리기 때문에 ★ 에 넣지 않았습니다 — 유일하게 ★ 가 대신해 주지 않는 단계입니다.

**총이 손에 안 맞을 때 (`그립 워크벤치` → `그립 저장` → ★)**
자동 계산은 총을 손 *근처*까지만 가져다 놓습니다. 몸통이 짧은 복셀 캐릭터에 0.6m 총을 쥐여 주면
기하학적으로 안 겹치는 답이 아예 없어서, 마지막 몇 cm는 사람 눈이 정해야 합니다.

1. `무기 — 그립 워크벤치` — 실제 게임에서 쓰는 **소총 파지 idle 자세로 포즈된** 미리보기가 씬에 생기고 `Weapon` 이 선택됩니다
2. 씬 뷰에서 `Weapon` 을 이동·회전·스케일로 맞춥니다 (기즈모를 **Local** 로 두면 편합니다)
3. `무기 — 포즈 순환` 을 반복해서 걷기·달리기·농땡이 자세에서도 확인합니다 (총은 손뼈의 자식이라 팔을 따라갑니다)
4. `무기 — 그립 저장` — 손뼈 기준 값이 `CastingConfig` 에 저장되고 `weaponGripManual` 이 켜집니다
5. `★ BUILD EVERYTHING` — 경호원·돌격대 전원에 같은 값이 적용됩니다

> **한 자세에서 맞추면 다른 자세는?** 총은 손뼈의 **자식**이라 매 프레임 계산 없이 팔을 그대로 따라갑니다.
> 그래서 손과의 관계는 절대 안 흔들립니다 (튀지 않습니다). 다만 *몸통과의* 관계는 클립마다 달라서,
> 예를 들어 농땡이(허리 굽힘) 자세에서 총이 다리를 스칠 수 있습니다. `포즈 순환` 은 그걸 미리 보라고 있는 겁니다.

> 값은 **미터로** 저장되고 회전은 손뼈 기준이라, 캐릭터마다 정규화 배율이 달라도 그대로 통합니다
> (전부 같은 믹사모 리그라서 손 축이 같습니다). 워크벤치 오브젝트는 지워도 되는 임시물입니다.
> 저장하면 총 **길이(`smgLength`)도** 같이 기록되므로, 총이 크면 워크벤치에서 줄이면 됩니다.

### 왼손 IK — `그립 저장` 이 같이 처리합니다

총은 오른손에 붙으므로 **왼손은 항상 거짓말**입니다. 걷기·달리기 클립은 총을 든 채로 만든 게 아니라
왼손이 허공을 젓습니다. `WeaponSupportIK` 가 왼손을 총열로 끌어옵니다.

**목표 지점을 추측하지 않습니다.** `그립 저장` 을 누르는 순간 캐릭터는 소총 파지 자세로 포즈돼 있고,
총은 방금 사용자가 그 자세에 맞춰 놓은 상태입니다. 그 때의 **'총 대비 왼손' 관계를 그대로 캡처**해서
다른 모든 클립을 그 관계로 되돌립니다. 애니메이터가 정한 파지 + 사용자가 정한 총 위치에서
자동으로 따라 나오는 값이라, 세 번째 추측이 필요 없습니다.

- 왼손이 총에서 **15cm 넘게** 떨어져 있으면 캡처를 거부합니다 (파지가 아니라 그냥 팔 위치이므로).
  이 경우 총열 덮개 부품(`*_BarrelGuard`)으로 대체하고 **위치만** 씁니다 — 부품 이름은 손목 각도를 알려주지 않으니까요.
- 권총은 `Pistol Idle` 기준으로 별도 왼손 IK를 캡처해 **양손 파지**로 사용합니다. SMG 캡처값과 공유하지 않습니다.
- 사망 시 0.2초에 걸쳐 풀립니다. 켜고 끄는 게 아니라 블렌드라 손이 순간이동하지 않습니다.
- 끄고 싶으면 `CastingConfig.leftHandIK`. 손목 각도만 빼려면 `leftHandIKRotationWeight = 0`.

> 팔이 짧은 캐릭터에 총이 길면 IK가 팔을 쭉 뻗어 버립니다. 그때는 워크벤치에서 **총을 줄이는 게** 답입니다.

**캐릭터를 추가/수정한 뒤 표준 순서**: `7` (리그) → `★ BUILD EVERYTHING`

## 3. 현재 상태

### ✅ 확인된 것 (플레이로 검증)
- NavMesh 베이크 — 경호원 이동 정상
- 첫 발 후 경호원이 **뛰어서** VIP에게 밀착
- 캐릭터가 바로 서 있음 (주저앉기 해결)
- 느낌표 크기 적절
- 8배율에서 250m 타겟 식별 가능
- 미션 씬 3개 생성 + NavMesh 데이터 6개 정상

### 🗂 지난 세션 수정 이력 (2026-09-01 · 원인 기록용)

> 아래는 **무엇을 왜 그렇게 고쳤는지**의 기록입니다. 되돌리기 전에 읽으세요.
> "지금 무엇을 확인해야 하는가"는 이 아래 🔵 절이 기준입니다.
- **무기 크기** — 캐릭터 정규화 스케일 상속 문제 수정 (SMG 0.6m / 권총 0.24m로 정규화)
- **죽는 모션** — 헤드샷/보디샷 구분 연결
- **총 잡는 자세** (2026-09-01) — 아래 두 가지를 같이 고쳤습니다. 하나만으로는 안 됩니다:
  - **무장 액터의 기본 idle을 `lookaround`(소총 파지)로 교체.**
    `Guard1Idle` 은 차렷이라 팔이 몸통에 붙어 있어서 총이 놓일 자리가 아예 없습니다.
    오프셋으로 고칠 수 있는 문제가 아니라 자세의 문제였습니다.
    VIP·민간인은 그대로 평범한 idle (`ActorRole.Civilian` 추가).
  - **`WeaponGrip` 이 총의 부품 이름을 읽고 잡는 지점을 계산.**
    바운딩 박스 중심이 아니라 `*_Trigger` 부품에 손을 맞추고,
    `*_Barrel` 위치로 총구 방향을, 방아쇠가 총열보다 아래라는 사실로 롤을 확정합니다.
    조준 방향은 **오른손→왼손 선** (양손 파지 idle이면 그게 곧 총열 방향).
- **`weaponGripOffset` 기본값 `(0, 0.03, 0)`** — z 보정은 이제 필요 없습니다 (그립 지점이 계산됨).
  y 0.03 은 총몸을 손목보다 살짝 올려 주먹이 손잡이를 감싼 것처럼 보이게 하는 값입니다.
- **조준 방향을 수평으로 평탄화** — 왼손이 오른손보다 높은 파지에서 총이 45° 들려
  개머리판이 가슴을 뚫고 내려가던 문제. 쉬는 자세의 총은 수평이므로 양손 선의 **요(yaw)만** 읽습니다.
- **수동 배치 (`그립 워크벤치` → `그립 저장`)** — 자동 계산으로는 한계가 있어서, 손으로 맞춘 값을
  `CastingConfig.weaponHandOffset/Euler` 에 저장하고 `weaponGripManual` 로 자동 계산을 끕니다.
  켜져 있으면 씬 생성 시점에 값이 구워지므로 **Play 안 해도 씬 뷰에서 바로 보입니다.**
- **왼손 IK (`WeaponSupportIK`)** — 걷기·달리기에서 왼손이 허공을 젓던 문제.
  생성기가 애니메이터 레이어의 **IK Pass 를 켭니다** (안 켜면 `OnAnimatorIK` 자체가 안 불립니다).
  목표 지점은 `그립 저장` 이 소총 파지 자세에서 캡처하고, 없으면 총열 덮개 부품으로 대체합니다.

- **DEFENSE 페이즈 전면 재설계** (2026-09-01) — 돌격대가 링 위 아무 점으로 직진하던 것을

## 4. 게임 구조

### OFFICE — 책상 위 서류 더미 (`BriefingController` / `RC_OfficeBuilder`)

캠페인이 시작하고, 매 계약 후 돌아오고, 끝나는 방. 빌드 인덱스 **0번**입니다.

**계약은 큐가 아닙니다.** 3건이 처음부터 전부 책상에 있고, 순서 상관없이 몇 번이든 고를 수
있습니다. 변하는 건 진행도가 아니라 **서류 자체**입니다 — 죽은 표적은 회색으로 죽고 도장이 찍히고,
살아서 도망친 표적은 그냥 그대로 남아 있습니다. **이게 실패 처리 설계의 전부입니다:
나쁜 판이 플레이어를 가둘 수 있는 상태가 존재하지 않습니다.** 재시도 프롬프트가 필요 없는 이유입니다.

**카드 3장이 아니라 서류 한 장입니다.** 카드 행 + 하단 상세 패널은 스테이지 셀렉트 위젯이었습니다 —
사진이 아이콘 크기로 줄고, 정작 계약 내용은 보고 있는 것 아래의 각주로 밀렸습니다. 서류철은 카드가
아닙니다. 그래서 **펼친 계약 하나가 패널 전체를 문서 크기로 쓰고**, 나머지 계약은 종이가 존재하는
방식으로 존재합니다 — **밑에서 삐죽 나온 모서리**로.

```
            ┌──────────────────┐ ← 뒤에 깔린 서류 (계약당 한 장, 클릭 가능)
        ┌───┴──────────────────┤
   ┌────┴─────────────────────┐│
   │ CONTRACT 3/3   난이도 ●●● │├ 모서리에 표시: 호박 = 미완료 / 빨강 = 사망
   │ WHEELS UP                ││
   │ ┌────────┐  표적이 헬기로…  ││
◀  │ │ 사진   │  경호  5명       ││  ▶
   │ │  (大)   │  거리  210m      ││
   │ └────────┘  탄약  3발       ││
   │  KAREL SIDOROV  21:12 …    ││
   └──────────────────────────┘┘
```

| 항목 | 내용 |
|---|---|
| 시점 | 책상 앞 **착석 고정**. 이동 없음, 마우스로 살짝 기웃거리는 패럴랙스만 (커서 잠금 안 함 — 메뉴니까) |
| 서류 넘기기 | **◀ ▶ 클릭** · **뒤에 깔린 서류 모서리 클릭** · 방향키 `← →` · `A`/`D` · 숫자 `1`~`3` |
| 수락 | `SPACE` (이미 제거한 표적이면 문구가 `re-run` 으로 바뀜) |
| 펼친 서류 | 코드명 · **난이도 3핍 + 라벨** · **큰 표적 사진** · 이름/신상 · 브리핑 문구 · 경호원 수 · 거리/고도차 · 지급 탄약 · 처리 기한 시각 · 픽업 시각 |
| 뒤 서류 | 모서리만. 이름은 안 보입니다 — 대신 **제거된 계약은 모서리가 빨갛습니다**, 그래서 남은 일감이 몇 개인지 더미만 봐도 읽힙니다 |
| 숫자 출처 | 전부 **같은 `MissionSet` 에서 복사**. 경호원 수는 진짜 경호원 수고, 픽업 시각 옆 유지 시간은 진짜 `survivalDuration` 입니다. 책상 위에 거짓말하는 장식은 없습니다 |

> 뒤 서류는 **보드 순서 그대로** 깔립니다 (열린 것만 빼고). 그래서 몇 번째 종이가 어느 계약인지가
> 선택을 옮길 때마다 뒤바뀌지 않습니다.

**난이도** — `MissionDefinition.difficulty` (1~3). 펼친 서류 우상단에 핍 3개 + 라벨:
`1 보통`(초록) / `2 어려움`(호박) / `3 극한`(빨강). 기본값은 HIGH TABLE 1 · STREET LEVEL 2 · WHEELS UP 3.

**표적 제거 표시** — 제거된 계약은 사진이 **어둡게 깔린 뒤 회색으로 덮이고**, 그 위에 −12° 기울어진
빨간 **"사망"** 도장이 크게 찍힙니다. IMGUI 에는 채도를 죽이는 블렌드가 없고 상태 하나 때문에
셰이더를 넣을 단계가 아니라, **2패스로 색을 회색 쪽으로 뭉갭니다** — 정장과 넥타이가 빨강/파랑이 아니라
톤으로 읽히면 목적 달성입니다. 진짜 그레이스케일이 필요해지면 그때 언릿 셰이더를 하나 넣으세요.

**사진은 이미지 파일이 아니라 라이브 렌더입니다.** 사무실 **600m 아래**에 조명 켜진 사진 부스가
**둘** 있고, 각자 전용 카메라로 RenderTexture 에 렌더합니다.

| 부스 | 피사체 | 텍스처 | 어디에 나오나 |
|---|---|---|---|
| `Booth_1..N` (x = 0, 12, 24…) | 계약별 **표적** — **전부 동시에 켜져 있음** | `DossierRT_1..N` 512×664 세로 | **보드 카드 3장** |
| `HeliBooth` (x=−60) | **탈출 헬기** (`Heli_2`, 뱅크된 3/4 뷰) | `HeliRT` 664×512 가로 | **책상 위 핀보드** |

> 보드가 카드 3장을 **동시에** 보여주므로 부스도 카메라도 텍스처도 **계약당 하나씩**입니다.
> 부스 하나로 피사체만 갈아 끼우면 나머지 두 카드가 낡거나 빈 이미지를 들고 있게 됩니다.
> 메뉴 프레임 예산에서 카메라 3대는 공짜입니다. 부스 간격 12m 는 포인트 라이트(사거리 7m)가
> 옆 부스에 닿지 않는 거리입니다.

- 왜 600m 아래인가: 한 씬에 조명 세트가 여럿이면 서로를 비춥니다. 레이어 마스킹보다 이게 확실합니다.
  두 부스도 같은 이유로 60m 떨어뜨렸습니다.
- 왜 PNG 로 굽지 않는가: 캐스팅을 바꾸면 **다음 빌드에 사진이 저절로 바뀝니다.** 잊어버릴
  내보내기 단계가 없습니다.
- **핀보드는 표적이 아니라 헬기입니다.** 표적 얼굴은 눈앞의 계약서에 이미 있고, 두 군데 있으면
  한 군데가 남습니다. 벽은 계약 사이에 플레이어가 사는 방이고, 거기 붙는 건 **돌아오는 쪽**입니다.
- **선택된 카드의 표적만 천천히 좌우로 돕니다** (`BriefingController.dossierSpinSpeed` 14도/초,
  `dossierSpinSweep` ±42도, 사인 곡선이라 양끝에서 부드럽게 꺾임). 360° 턴테이블이 아닌 이유:
  한 바퀴의 절반은 뒤통수고, 뒤통수는 신상 파일에서 아무것도 말해 주지 않습니다.
  `dossierSpinSweep = 0` 으로 두면 한 방향 무한 회전이 됩니다.
  씬은 재생성되므로 **인스펙터가 아니라 스크립트 기본값**을 고치세요.
- 헬기 부스의 로터는 **안 돕니다.** 코르크에 핀으로 꽂은 사진인데 내용물이 움직이면 모니터로 읽힙니다.
- 표적 부스의 인물은 `ActorRole.Vip` 로 스폰합니다 (클립 탐색이 파일명의 `vip` 태그를 보기 때문 —
  Civilian 으로 스폰하면 VIP 전용 idle 을 거부하고 남의 포즈로 서 있습니다).
- 히트박스/사망/콜라이더는 전부 제거합니다. 사진이지 표적이 아닙니다.
- 핀보드 Quad 의 가로세로비는 `HeliRT` 비율에 맞춰 두었습니다 (`photoW/photoH` = 1.30).
  **텍스처 크기를 바꾸면 Quad 스케일도 같이** 바꿔야 헬기가 안 늘어납니다.

### 캠페인 상태 (`CampaignState`)

진행도가 아니라 **플래그 집합**입니다: 계약별로 "이 표적이 죽었는가" 하나씩 (`rc.down.<i>`).
순서가 없으니 "어디까지 갔는가"라는 값 자체가 존재하지 않습니다. `rc.cursor` 는 보드가 열릴 때
커서를 어디 둘지일 뿐입니다.

**보드에 도장을 찍는 기준은 계약이 아니라 표적입니다** — `targetEliminated` 가 true 면 찍힙니다.
헤드샷을 넣고 방어전에서 죽어도(K.I.A.) 표적은 죽은 겁니다. 그래도 손해는 없습니다:
**모든 계약은 언제나 다시 선택 가능**하니까요.

| 결과 | 보드 |
|---|---|
| 표적 사망 (COMPLETE, 또는 죽이고 전사) | 카드 회색 + **"사망"** 도장 |
| 표적 생존 (PARTIAL / K.I.A.) | 그대로 남음 — 다시 고르면 됨 |

**`DontDestroyOnLoad` 싱글턴이 아닌 이유**: 이 프로젝트는 씬을 생성하고 그 씬에서 바로 Play 를
누르는 식으로 테스트합니다. 싱글턴이면 사무실에서 시작하지 않은 `Mission2.unity` 는 단독으로
못 돌립니다. PlayerPrefs 는 어느 씬에서 Play 를 눌러도 동작하고, 덤으로 중간에 끄고 켜도 이어집니다.

기록 시점은 결과 화면을 **넘길 때가 아니라 미션이 끝나는 순간**(`MissionDirector.End`)입니다.
결과 화면에서 게임을 꺼도 표적은 죽은 채로 남습니다.

### 페이즈
```
PREP ──첫 발사──▶ ENGAGED ──+N초──▶ DEFENSE ──N초 생존──▶ [EXFIL 7초] ──▶ RESULT ──SPACE──▶ Office
```
- **PREP**: 자유 조준, 시간 무제한 (미션3만 `strikeWindow` 75초)
- **ENGAGED**: 경호원 머리 위 `!`, VIP에게 밀착 대형(호 형태), VIP 대피 시작. **17초 (전 계약 동일)**

> **페이즈 전환과 경보는 시점이 다릅니다.** 페이즈는 **발사 순간**(`ReportSniperShot`)에 넘어가지만,
> 경호원이 반응하는 건 **탄이 도착한 순간**(`ReportSniperImpact` → `FirstSniperImpact`)입니다.
> 250m 에서 탄이 0.96초를 나는데 발사와 동시에 `!` 가 뜨면, 경호대가 **총알보다 먼저** 아는 그림이
> 됩니다. 빗나간 첫 발도 착탄해야 경보가 나므로 "빗맞혔는데 들켰다"가 성립합니다.
> `ProtectionDetail` 은 `FirstSniperImpact` 를 듣습니다 — **`FirstShotFired` 로 되돌리지 마세요.**
- **DEFENSE**: 뒤쪽 **계단실 문 하나**에서 돌격대가 계속 나옴, 3단계로 밀고 들어옴 (아래 참고)
- **EXFIL**: 생존 시간 만료 = 미션 종료가 아니라 **헬기 호출**. 헬기가 들어오는 동안 플레이어는
  **같은 자리에서 계속 싸웁니다.** 도착하면 RESULT.
- **RESULT**: 클리어 시 `SPACE`로 다음 계약, `R`로 재시도

### SNIPER 페이즈 — 영점 · 거치 소총 · 반동 (2026-09-02 재설계)

스코프 안쪽이 통째로 다시 만들어졌습니다. 네 가지가 **서로 맞물려 있어서** 하나만 되돌리면 깨집니다.

#### 1. 영점 (`SniperRig.zeroRange`) — 조준점을 정직하게

영점이 없으면 250m 에서 탄이 **머리 하나만큼 낮게** 떨어집니다 (낙차 0.44m vs 머리 박스 0.43m).
즉 머리에 조준점을 정확히 올리면 **목에 맞습니다.** 플레이어가 배울 수 있는 게 아니라 그냥 거짓말하는
조준점이었습니다.

- 생성기가 계약의 **경사거리**로 굽습니다: `√(거리² + 고도차²)`.
  미션2는 300m 아래로 58m 이므로 **305.6m** 로 영점이 잡힙니다 — 탄이 실제로 나는 거리가 그것이니까요.
- 낙차 물리는 **손대지 않았습니다.** 총열만 조준선 위로 살짝 들어 올려(`ZeroElevationDeg`)
  탄도가 영점 거리에서 조준선과 다시 만나게 합니다. 실제 소총 영점과 같은 방식입니다.
- `ZeroElevationDeg` 는 `Projectile` 이 적분하는 것과 **같은 물리에서 유도**되므로 둘이 어긋날 수 없습니다.
- 인스펙터에서 보이라고 런타임 계산이 아니라 **씬 생성 시점에 굽습니다** (탄약 수 옆에 있는 게 맞는 값이라).

> **스코프의 탄낙차 사다리는 지웠습니다.** 눈금이 화면 반지름 기준이라 **배율마다 다른 홀드**를
> 뜻했고, 미터로는 아무것도 뜻하지 않았습니다 — 플레이어에게 틀린 것을 가르치는 눈금이었습니다.
> 영점이 착탄점을 중앙 십자에 올려 주므로 사다리는 **낮게 조준하라고 유혹하는 역할**밖에 없습니다.

#### 2. 반동 — 카메라에서 소총으로 옮김

`recoilPitchKick` **6.5° → 2.2°**. 8배율에서 스코프 전체가 7.5° 인데 6.5° 를 걷어차면
0.96초 탄 비행 중 **0.65초 동안 표적이 화면 밖**이었습니다. 플레이어가 자기 탄이 날아가는 걸
아예 못 봤다는 뜻입니다.

잃은 타격감은 **`MountedRifleView`** 가 받습니다 — 소총 모델이 삼각대 위에서 0.17m 뒤로 밀렸다
9배속으로 돌아옵니다. **조준선을 표적에서 떼지 않으면서** 반동이 읽힙니다.

> 복귀는 여전히 **과보정 없는 임계감쇠**라 쏘기 전 조준점에 **정확히** 되돌아옵니다.
> 복귀 0.65초가 탄 비행(0.82~1.18초)보다 **짧다**는 순서가 이 페이즈의 전부입니다 —
> 4절 "핵심 템포" 참고.

#### 3. 거치 소총 (`MountedRifleView`)

소총은 **카메라의 자식이 아닙니다.** 난간에 거치된 채 월드에 고정돼 있고, 총열만 조준을 따라갑니다.

- 회전축이 개머리판도 카메라도 아닌 **삼각대가 짚은 지점**입니다. 그 뒤 삼각대를 역보정해서
  **발이 난간 캡에서 절대 안 떨어집니다**.
- 스코프에 들어가면(배율 > 1x) 소총 렌더러를 **끕니다** — 조준경 안에서 총몸이 화면을 가리니까요.
- 계약마다 위치가 다릅니다 (`playerRifleLocalPosition/Euler`). 맞추는 법은 2절
  `무기 — 플레이어 소총 배치 저장` 참고.

#### 4. 인트로 워크 (`PlayerIntro`)

시작하면 **4.5m 를 3.2초에 걸어가** 이미 거치돼 있는 소총 앞에 섭니다. 도착 전까지 `BlocksInput`.

- 걸을 때 카메라가 미세하게 **위아래로 흔들립니다** (양 끝에서 사인으로 잦아듦).
- 도착해도 소총을 **카메라에 붙이지 않습니다.** 조작만 활성화됩니다 — 그게 "설치된 무기를
  잡는다"로 읽히고, 손에 든 총을 난간에 올리는 것과 다른 그림입니다.

### EXFIL — 헬기 탈출 (`HeliExtraction`)

**페이즈 enum은 4개 그대로입니다.** EXFIL 동안 `Phase` 는 여전히 `Defense` 이고
`MissionDirector.IsExtracting` 플래그만 켜집니다. `Phase == Result` 를 검사하는 코드가
5군데라 다섯 번째 값을 넣으면 하나 빠뜨렸을 때 조용히 깨집니다.

| 항목 | 값 / 동작 |
|---|---|
| 기체 | `Heli_2` (동축 반전 로터 — `Rotor_Twin_Upper/Lower` 를 서로 반대로 돌립니다) |
| 진입 | 앞쪽 왼편 아래에서 베지어 곡선으로 상승 진입, 선회 시 최대 22° 뱅크 |
| 호버 | **앞 난간 너머** `NestCenter + (3, 3.4, 18)` — 도시 조망 쪽 |
| 전투 개입 | **없음.** 무장도 콜라이더도 없습니다 |
| 스폰 | 탈출 시작 = `AssaultDirector` 스폰 중단. **이미 옥상에 있는 특공대는 계속 싸웁니다** |

**왜 착륙 안 하고 호버하는가**: 착륙할 옥상 바닥이 곧 전장입니다 (STAGE 1~3 엄폐물이 깔려 있음).
그리고 앞 난간 쪽에 띄우면 **탈출을 보려면 특공대에게 등을 돌려야 합니다** — 문은 정반대편입니다.

**왜 헬기가 안 쏘는가**: 플레이어가 아직 싸우는 중에 도착하는 게 설계입니다.
헬기가 옥상을 정리해 버리면 마지막 몇 초가 조용해집니다.

### DEFENSE 페이즈 설계 — 옥상 기계실 덱

플레이어 옥상을 뒤로 14m 늘려서 (`NestSizeZ` 20 → 34, 덱 중심 z −7) 돌격대가 건널 거리를 25m 확보했습니다.
**저격하는 앞쪽(+Z)은 좌표가 그대로**입니다 — 카메라 피치와 난간 높이가 그 값에 맞춰 튜닝돼 있어서
건드리면 저격 페이즈가 같이 망가집니다. 늘린 건 전부 플레이어 **뒤쪽**입니다.

```
 z +10   앞 난간 (저격 방향, 도시 조망)
 z  +4   ■■■■■■■■■■■■■  플레이어 엄폐벽 (13m) — 양끝 7m 는 열림 = 최종 돌입 통로
 z  -2   ▣    ▣          STAGE 3  실외기 한 쌍 · 자리 2개 · 7m
 z  -8   ▤  ─────  ▤     STAGE 2  공조기(완전엄폐) + 덕트(허리높이) · 자리 4개 · 13m
 z -14   ▥   ▥    ▥      STAGE 1  냉각탑 뱅크 · 자리 5개 · 19m
 z -18.4          ▪      스폰 지점
 z -21.6  ┌──[문]──┐     계단실 (3.8m) — 모든 돌격대가 여기서 나온다
```

**접근을 세 가지가 통제합니다. 전부 개별 AI가 아니라 디렉터에 있습니다:**

| 장치 | 내용 |
|---|---|
| **자리(slot)** | 단계별 엄폐 지점 수가 고정이고 **배타적**입니다. STAGE 3 는 **2개뿐** — 몇 명이 살아있든 플레이어 근처에는 최대 2명입니다. 나머지는 뒤에서 자리가 비기를 기다립니다 |
| **허가(permit)** | 개활지를 건너는 인원은 동시에 **1명**(후반 2명). 나머지는 그동안 전부 엄폐 중입니다 |
| **엄호사격** | 다른 누군가가 **실제로 몸을 내밀고 쏘는 중**일 때만 전진 허가가 납니다. 아무도 안 쏘면 아무도 안 움직입니다 |

문에서 나오는 첫 도약만 예외입니다 (열린 문에 서 있는 게 더 나쁘고, 아직 엄호해 줄 사람도 없음).
결과적으로 **도약전진(bounding overwatch)** 이 되고, 플레이어 쪽에서는
"기계 한 줄씩 뺏기며 밀린다"로 읽힙니다.

**개별 병사 행동** (`AssaultGuard.Stance`)

| 상태 | 내용 |
|---|---|
| `Deploy` | 문에서 나와 1선 엄폐로. 달리는 중엔 사격 안 함 |
| `Hold` | 엄폐 뒤. `exposeTime`(1.2~2.6초) 옆으로 나와 쏘고 `hideTime`(1.4~3.4초) 숨습니다. 사수가 좋을수록 오래 나와 있고 짧게 숨습니다 |
| `Advance` | 다음 단계로 도약. 허가 + 빈 자리 + 엄호사격이 다 맞아야 시작 |
| `Push` | 최종 돌입. 생존시간 **55% 경과** 후, 한 번에 1명(후반 2명) |

- **피격 시 후퇴**: 체력이 45% 아래로 떨어지면 **한 단계 물러납니다** (1회 한정).
  플레이어가 맞췄다는 게 눈에 보이고, 가까운 자리가 다시 열립니다.
- 문에서 첫 STAGE 3 도달까지 **최소 13~21초**. 40초 방어전에서 근접 위협은 중반에 옵니다.

**엄폐가 진짜인지 확인하는 법**: 병사 총구 높이 1.3m, 엄폐물은 2.0~3.5m 입니다.
엄폐물을 낮추면 (또는 캐릭터 키를 키우면) 전부 무의미해집니다.
가운데 덕트만 **윗면 1.25m** 로 일부러 낮습니다 — 가운데 차선으로 오는 놈은 상체가 보입니다.

### 2026-09-02 — 사격판정이 애매하던 진짜 이유

증상은 "엄폐물이 촘촘해서 어디를 쏴야 할지 모르겠다" 였지만, 원인은 촘촘함이 아니라 **폭**이었습니다.

`CoverPoint.peekOffset` 기본값이 **1.15m** 인데 `AddCover()` 가 그 값을 **한 번도 설정하지 않았고**,
실제 엄폐물은 2.4 ~ **5.0m** 폭이었습니다. 즉 **모든 병사가 "몸을 내밀어도" 자기 엄폐물 뒤였습니다.**
플레이어에게는 실루엣 조각만 보이고 총알은 케이싱에 맞았습니다.

| 엄폐물 | 폭 (이전 → 지금) | 필요 peek | 이전 peek |
|---|---|---|---|
| CoolTower A/B/C | 3.4~3.8 → 3.0~3.4 | 1.95~2.15 | 1.15 |
| CondBank L/R | 2.4 → 2.6 | 1.75 | 1.15 |
| **AHU L/R** | **5.0 → 3.2** | **2.05** | 1.15 |
| Condenser L/R | 2.6 → 2.4 | 1.65 | 1.15 |

**수정 내용**
- `AddCover(..., coverWidth)` 로 폭을 넘겨 **`peekOffset = 반폭 + 0.45`** 자동 계산.
  `ShoulderClearance = 0.45f` 가 그 어깨 여유입니다.
- AHU 를 5.0 → 3.2m 로 축소. 5m 폭에 자리 하나를 가운데 박아 두면 **나올 수 있는 방향이 없습니다.**
- **`VentStack` 을 x=0 에서 좌측 플랭크로 이동.** 2.3m 기둥이 엄폐 앵커 정면 5.5m 에 서 있었습니다 —
  방어 페이즈에서 가장 중요한 사격선이 기둥으로 막혀 있었다는 뜻입니다.
- **덕트 윗면 1.70 → 1.25m.** 플레이어 피킹 시 눈높이가 `0.85 + 0.85 = 1.70` 이라 **정확히 같은 높이**였고,
  시선이 덕트 립을 스쳐서 "가운데 차선은 상체가 보인다"는 문서 설명이 **사실이 아니었습니다.**
- `Duct_Elbow` 를 x=3.2 (근거리 중앙 차선) → 4.6 으로 이동.

**앞으로 플랜트를 옮길 때 지켜야 할 두 규칙** (하나라도 깨면 AI 를 아무리 잘 짜도 뭉개집니다):
1. 엄폐물 폭은 **최대 ~3.4m**, 그리고 자리의 peek 은 **그 폭에서 계산**할 것. 넓은 엄폐물은 나올 수가 없습니다.
2. 플레이어의 **중앙 시선(x=0, z=+5.3 기준)** 은 STAGE 3 부터 냉각탑까지 **뚫려 있을 것.**
   그 선 위에 있어도 되는 건 문을 가리는 `CoolTower_B` 하나뿐입니다.

### 계약 3종 (`MissionSet.asset`)

**저격 포인트는 3계약 모두 같은 옥상입니다.** 방어 페이즈 전체가 그 지붕 하나에 레벨 디자인으로
박혀 있어서, 옥상을 계약마다 새로 만들면 계약마다 다시 튜닝해야 합니다. 계약을 다르게 만드는 건
**스코프 반대편에 뭐가 있느냐**(= 베뉴)이지 스코프의 위치가 아닙니다.

| | 코드명 | 베뉴 | 거리/고도 | 탄 | 경호원 | 침투 | 생존 | 동시생존 | 스폰간격 | 하늘 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | HIGH TABLE | `RooftopTerrace` (y=34) | 250m / +30m | 6 | 3 | 17s | 40s | 5 | 3.5~7s | 노을 |
| 2 | STREET LEVEL | `StreetWalk` (**y=0**) | 300m / **+58m** | 5 | 4 | 17s | 40s | 6 | 3~6s | 황혼 |
| 3 | WHEELS UP | `Helipad` (y=34) | 210m / +42m | **4** | **5** | 17s | 40s | **8** | 2.2~5s | 밤 |

> 미션3만 `strikeWindow` **75초** (표적이 헬기로 걸어가는 시간). 나머지 둘은 무제한.

> **두 시계는 세 계약이 전부 같습니다 (의도).** 예전엔 30/25/20 · 60/75/90 으로 램프였는데,
> 그건 "1→2→3 순서로 한다"는 전제를 값에 박아 둔 것이었습니다. **보드에서 아무거나 고르는 순간
> 그 전제가 죽었습니다** — 12초 신관은 마지막 판으로는 좋고 첫 판으로는 최악인데, 3번을 첫 판으로
> 고르는 걸 막는 게 아무것도 없습니다. 통일하면 **"첫 발 후 17초, 그다음 40초 유지"** 가 한 번 배우면
> 전 계약에 통하는 규칙이 됩니다.
>
> 램프가 사라진 게 아니라 **난이도 핍이 실제로 가리키는 곳으로 옮겨갔습니다**: 탄약(6/5/4),
> 경호원(3/4/5), 베뉴, 그리고 돌격대 **밀도**(`assaultMaxAlive` 5/6/8 · `assaultSpawnInterval`).
> 계약은 **길어져서가 아니라 빽빽해져서** 어려워집니다.
>
> 40초로 줄여도 안전한 이유: `AssaultDirector` 의 모든 수치가 `survivalDuration` 기준 **비율**입니다
> (`Progress()`). 곡선이 잘리는 게 아니라 **압축**되므로 접근 단계가 조용히 사라지지 않습니다.
> 40초면 최종 돌입 해금(`pushUnlockProgress` 0.55)이 **22초** — 1선이 STAGE 3 에 닿는
> 13~21초 직후입니다. 60초일 땐 33초라 양쪽이 그 간격을 서로 쳐다보며 보냈습니다.

> ⚠️ **`MissionSet.asset` 과 `BuildDefaults()` 를 같이 고치세요.** 인스펙터에서만 바꾸면
> `assetVersion` 이 올라가는 순간 생성기가 `BuildDefaults()` 로 **덮어씁니다**. 현재 `assetVersion` = **7**.

**세 계약은 세 종류의 사격입니다** — 같은 표적을 세 번 쏘는 게 아니라:

1. **정지 표적.** 거리와 호흡, 그 외엔 없음. 튜토리얼.
2. **도보 이동 표적.** 표적이 **X축으로 걷고 플레이어는 Z축을 봅니다** — 이동 전량이 순수 횡방향이라
   **리드 사격**이 강제됩니다 (300m 탄 비행 0.75초 × 보행 1.2m/s ≈ 몸통 하나). 인도 옆 주차 차량 ·
   버스쉘터 · 가로수가 **간헐적 차폐**라, 창이 열렸다 닫힙니다. 플레이어는 "쏠까"가 아니라 "언제"를 고릅니다.
   1번에서 배운 "가만히 기다린다"가 여기선 빗나갑니다.
3. **탑승 직전 표적.** 로터가 이미 도는 헬기까지 40m를 걸어가고, **타면 계약 종료**. 유일하게
   시계가 붙는 계약이고, 그 시계는 눈에 보입니다 (걸어가는 사람). 패드는 일부러 휑합니다 —
   사격을 막는 건 잡동사니가 아니라 경호원 5명의 몸입니다.

> 옛 문서의 "미션 2는 고도를 낮춰 부감을 얕게" 는 **폐기**했습니다. 지금 미션 2는 반대로 표적을
> 34m 아래 도로로 내려서 부감 11°로 **깊게** 만듭니다. 난이도는 각도가 아니라 리드입니다.

**베뉴가 생성기에 넘겨야 하는 4가지** (`RC_MapBuilder.BuildTargetVenue`):
NavMesh 가능한 바닥 · `targetSpawn` · 표적 경로(`vipWaypoints`) · 경호원 자리(`guardPosts`).
`targetOneWayRoute` / `targetEscapesAtEnd` 를 켜면 표적이 순찰 대신 **한 번만 걷고 사라집니다**.

### 걷는 표적의 죽은 시간 메우기 — 자막 + 창 카운트다운

미션 2·3 은 표적이 20~40m 를 걸어오는 동안 아무 일도 안 일어납니다. **시간이 길어서가 아니라
설명이 없어서** 8배율 안이 정지 화면처럼 보였습니다. 두 개를 붙였습니다.

**1. 자막 (`SubtitleFeed` + `RouteNarrator`)** — VIP 웨이포인트 도달마다 한 줄:

```
표적 하차 확인. 좌측 인도, 로비까지 도보로 이동 중.
주차 차량 구간 진입 — 차 사이로 시야가 끊긴다. 빈 곳을 노려라.
버스 정류장 통과. 로비까지 얼마 안 남았다.
표적 로비 진입. 계약 종료.
```

- 대사는 **베뉴가 씁니다** (`MapRefs.routeCues`). 3번 웨이포인트에 버스정류장이 있다는 걸 아는 건
  버스정류장을 거기 놓은 코드니까요. `MissionSet` 에 적으면 소품을 옮기는 순간 해설이 어긋납니다
- **정지 표적 계약(미션1)에는 나레이터를 아예 안 붙입니다.** 아무 일도 없을 때 떠드는 HUD 는
  플레이어에게 HUD 를 안 읽는 습관을 가르칩니다
- `VipTarget.WaypointReached` 는 **도착이 아니라 출발** 시점에 발화합니다 — 덕분에 첫 프레임에
  인덱스 0 이 나가서, 걷기 시작하기 전에 첫 줄이 뜹니다

**2. 등장 카운트다운** — `TARGET APPROACHING · 5s`. **접근 구간에만** 뜹니다.

표적이 `inPlayWaypoint`(기본 1)에 닿는 순간 사라집니다. 그 뒤로는 아무 숫자도 안 띄웁니다.

> **왜 "빠져나가기까지 N초"는 안 띄우는가.** 한 번 넣었다가 뺐습니다. 표적이 로비 문 쪽으로
> 걸어가는 건 **이미 화면에 보입니다** — 같은 걸 숫자로 또 세는 건 HUD 가 스코프에 보이는 걸
> 되풀이하는 겁니다. 스코프가 못 보여주는 유일한 구간은 **사정권에 들어오기 전**(화면 구석의 점이거나
> 아예 프레임 밖)이고, 카운트다운은 거기에만 붙습니다.
>
> 시계가 붙는 예외는 `MissionDefinition.strikeWindow` 를 가진 계약(미션3, 75초)뿐입니다.
> 그건 표적의 이탈이 아니라 **미션이 건 제한**이라 화면에 단서가 없습니다.

### 이동 호위 대형 (`ProtectionDetail.escortWhileCalm`)

**걷는 표적에는 걷는 경호가 붙습니다.** `ProtectionDetail.Update()` 가 원래 `alerted` 일 때만 돌아서,
첫 발 전에는 경호원이 자기 스폰 자리 반경 2.2m 를 배회할 뿐이었습니다. 정지 표적(미션1)에는 맞지만
**걷는 표적(미션2·3)은 그냥 두고 갔습니다** — 지키는 사람이 혼자 걸어가는 그림이었습니다.

- **진행 방향 기준 타원**으로 VIP를 둘러쌉니다. 1번이 선두, 나머지는 균등 분배, 전원 **바깥을 봅니다**
- 정원이 아니라 타원인 이유: 도로 미션 인도가 **폭 7m** 뿐이라 반경 3.4m 정원이면 측면 경호원이
  연석 밖으로 밀립니다. `escortLateralScale` 0.7 → 앞뒤 ±3.4m / 좌우 ±2.4m
- 대형이 **VIP 헤딩에 묶여 있어서** 코너에서 통째로 같이 돌아갑니다 — 선두는 계속 선두입니다
- 이동 중에는 에이전트가 진행 방향으로 몸을 돌리고, **자리에 도착한 뒤에만** 바깥쪽으로 돌아섭니다.
  내내 바깥을 보게 하면 게처럼 옆걸음으로 걷습니다
- `escortSpeed` 2.2 m/s — VIP 보행 1.2보다 빨라야 자리를 유지합니다. 같으면 한 번 뒤처진 뒤
  영원히 못 따라잡습니다
- 자리가 `escortRepathDistance`(0.45m) 넘게 움직였을 때만 경로를 다시 잡습니다. 매 프레임
  `SetDestination` 하면 에이전트가 제자리에서 떱니다

> 켜고 끄는 건 생성기가 `map.targetOneWayRoute` 로 결정합니다 — 베뉴가 "걷는 표적을 만들었다"고
> 이미 말해 주는 플래그라, 둘이 어긋날 수가 없습니다. **미션1은 끕니다**: 회합장에서 경호원이
> 원을 그리고 도는 건 이상하고, "경호는 느슨하다"는 그 계약의 설계이기도 합니다.

### 표적이 살아서 빠져나가는 경우 (`ReportTargetEscaped`)

| 상황 | 결과 |
|---|---|
| PREP 중 (아직 한 발도 안 쏨) | **즉시 미션 종료, PARTIAL.** 아무도 저격수가 있었다는 걸 모르니 방어할 게 없습니다 |
| ENGAGED 이후 | 옥상은 이미 오고 있으므로 **전투는 그대로 끝까지**, 계약만 PARTIAL |

`MissionDefinition.strikeWindow > 0` 인 계약은 PREP 에 카운트다운이 붙고 (HUD 하단, 15초 남으면 빨강),
만료 시 디렉터가 `ReportTargetEscaped()` 를 부릅니다. **미션 3만 75초**로 켜져 있습니다.
`VipTarget` 은 `TargetGotAway` 이벤트를 듣고 스스로 비활성화됩니다 — 경로 완주로 빠져나갔든
시계가 만료됐든 **한 경로로 수렴**시키기 위해서입니다 (HUD 는 사라졌다는데 헬리패드엔 서 있는 그림 방지).

### 조작
| 입력 | SNIPER | DEFENSE |
|---|---|---|
| 우클릭 | 배율 **1x → 8x → 16x** 순환 | 홀드 = 엄폐 해제 |
| 좌클릭 | 사격 | 사격 |
| A / D | — | 난간 따라 좌우 |
| R | — | 재장전 / 결과창 재시작 |
| Shift | 호흡 정지 (흔들림 0.18배) | — |
| SPACE | — | 결과창에서 다음 계약 |
| **ESC** | **일시정지 메뉴** | **일시정지 메뉴** |

**ESC 일시정지 메뉴** (`HudController`) — `게임으로 돌아가기` / `미션 포기 · 사무실로 복귀`.
브라우저에서 도는 게임이라 나갈 방법이 필요하고, 계약이 언제나 다시 선택 가능하므로
**중도 포기에 벌칙이 없습니다** — 표적을 이미 죽였다면 그 도장은 그대로 찍힙니다.

### 핵심 템포 (의도된 설계)

**한 발의 리듬: 발사 → 조준점 복귀 → 착탄 → 노리쇠.** 이 순서가 절대 뒤집히지 않게 잡혀 있습니다.

| | 값 | 근거 |
|---|---|---|
| 조준점 복귀 | **0.65초** (0.10 상승 + 0.55 복귀) | 임계감쇠라 과보정 없이 쏘기 전 지점에 **정확히** 돌아옵니다 |
| 탄 비행 | **0.82 ~ 1.18초** | 탄속 260m/s ÷ 계약별 **경사거리** (미션3 214m · 1 250m · 2 306m) |
| 노리쇠 | **1.2초** | 탄 비행보다 **길다** — 다음 발을 쏘기 전에 반드시 자기 착탄을 봅니다 |

복귀(0.65)가 비행(0.82~1.18)보다 **짧다**는 게 핵심입니다. 조준점이 먼저 자리를 잡고,
그 안정된 스코프로 자기 탄이 도착하는 걸 봅니다. 순서가 뒤집히면 (반동이 더 길면) 착탄이
흔들리는 화면에서 일어나고, 플레이어는 자기가 어디를 맞혔는지 **알 수 없습니다.**

> 탄속을 **올리면** 비행이 복귀보다 짧아져 이 순서가 깨집니다. 반동 시간을 **늘려도** 같습니다.
> 두 값 중 하나를 건드릴 거면 다른 하나를 같이 보세요.

> 탄속 260m/s 는 실총보다 한참 느립니다 — 210~300m 에서 "쏘고 · 복귀하고 · 맞는" 박자가
> 읽히게 만든 값이고, 그 이상 느리면 총알이 눈에 보이게 떠다닙니다.
> **반동 크기(2.2°)는 이 표와 별개**입니다 — 4절 "SNIPER 페이즈" 참고.

## 5. 캐릭터 파이프라인

**MagicaVoxel → 믹사모 오토리깅 → Unity**. 전부 **Humanoid**라 클립 1개가 전 캐릭터에 리타게팅됩니다.

```
Assets/VoxelCharacter/
  Vip1/  Vip2/  Vip3/     VIP 3종 (미션당 1명)
  Guard1/ Guard2/          경호원 2종 (섞여서 배치)
  Assault/                 돌격대
  Player/                  ← 1인칭이라 미사용
  _Animations/             공용 클립 폴더 (현재 비어 있음, 인식됨)
```

### 클립 탐색 규칙 — **파일명 기준** (클립 이름 아님)
믹사모가 클립을 캐릭터 이름으로 저장하기 때문입니다 (`Guard2Idle.fbx` 안의 클립명은 `Guard2`).

| 키워드 | 용도 |
|---|---|
| `lookaround` | **무장 액터(경호원·돌격대)의 기본 대기.** 소총을 든 자세라 총이 제자리에 놓인다 |
| `idle` | 대기 (Humanoid는 **필수** — 없으면 주저앉음). VIP·민간인의 기본, 무장 액터는 `lookaround` 가 없을 때의 폴백 |
| `walk` | 걷기 |
| `run` | 달리기 |
| `checkshoe` | 농땡이 idle (경호원 한 명만, 35% 확률) |
| `headshotdeath` / `bodyshotdeath` / `death` | 사망 |

> `lookaround` 와 `checkshoe` 는 **무장 역할에만** 배정됩니다. 둘 다 소총을 든 채로 만들어진
> 클립이라 VIP나 민간인에게 붙으면 없는 총을 들고 흉내내는 그림이 됩니다.

**탐색 순서**: 본인 폴더 → `_Animations` → 다른 캐스팅 폴더
**같은 키워드에 여러 파일이 걸리면 → 파일명이 가장 짧은 것** (수식어 없는 게 "그냥 idle")
**역할 태그**: 파일명에 `vip` 가 있으면 VIP 전용, 없으면 가드용 (`VIPRunning` vs `Guard1RifleRun` 구분)

### 캐릭터 추가 시 체크리스트

## 6. 이미 밟은 지뢰 — **다시 밟지 말 것**

이 프로젝트에서 실제로 발생했고 원인까지 규명된 문제들입니다. 코드에 주석으로도 남겨뒀습니다.

| 증상 | 진짜 원인 |
|---|---|
| **NavMesh가 통째로 안 됨 (4라운드 소모)** | `BuildNavMeshData(..., Vector3.zero)` 로 굽고 `AddData()` 는 `transform.position` 에 붙임 → 옥상(y=34)이 y=68에 생성. **좌표계 불일치**. 서피스 GO는 반드시 월드 원점에 둘 것 |
| NavMesh 수집 결과 0개 | `NavMeshSurface` 의 에디터 수집 경로(`CollectSourcesInStage`)가 생성기 컨텍스트에서 빈 결과 반환. → **MeshFilter를 직접 순회**해서 소스를 만든다 |
| `BuildNavMesh()` 후 데이터가 사라짐 | 메모리에만 생성됨. `AssetDatabase.CreateAsset` 를 직접 호출해야 함 |
| NavMesh 검증이 항상 실패 | `CreateAsset` 이 오브젝트를 재배치해 런타임 인스턴스가 떨어짐. **저장 전에** 검증할 것 |
| 캐릭터 키가 목표치와 안 맞음 | `Renderer.bounds` 는 스킨드 메시에서 **패딩된 값**(약 11% 큼). `BakeMesh` 정점으로 실측할 것 |
| 정규화 후 키가 오히려 커짐 | `BakeMesh` 출력에 계층 스케일이 이미 포함 → `localToWorldMatrix` 를 또 곱하면 제곱. **두 행렬 후보를 `renderer.bounds` 와 대조해 자동 선택**하게 해둠 |
| 총이 가슴을 관통 | 로컬 중심점 오프셋에 역회전을 이중 적용 |
| 총이 사람보다 큼 | 손뼈가 캐릭터 정규화 스케일(약 1.53배)을 갖고 있어 무기가 상속 |
| **총 잡는 자세가 계속 어색함** | **오프셋이 아니라 idle이 원인.** 차렷 자세(`Guard1Idle`)에는 총이 놓일 자리가 없다 → 무장 액터는 `lookaround`(소총 파지)를 기본 루프로 |
| 총을 서류가방처럼 가운데를 쥠 | 바운딩 박스 중심을 손에 맞추고 있었음. 총은 방아쇠를 쥔다 → `*_Trigger` 부품 위치로 그립 지점 계산 |
| 총이 뒤집히거나 뒤로 향함 | `FromToRotation` 은 180° 회전축을 임의로 고른다 (롤 미정의). `LookRotation(총열, 총의 위)` 의 역으로 프레임 전체를 확정할 것. 총열 방향은 `*_Barrel` 부품, 위쪽은 "방아쇠는 총열 아래" 로 판정 |
| 총이 45° 들려 개머리판이 가슴을 뚫음 | 양손 선을 **그대로** 조준 방향으로 씀. 왼손(지지손)이 오른손보다 높아서 총 전체가 들린다 → 액터 수평면에 투영해 **yaw만** 쓸 것 |
| **자동 배치로는 끝까지 안 맞음** | 몸통이 짧은 복셀 캐릭터 + 0.6m 총은 **겹치지 않는 해가 없다**. 규칙을 하나 더 짜지 말고 `그립 워크벤치` 에서 눈으로 맞춰 `CastingConfig` 에 저장할 것 (씬은 재생성되므로 씬에서 직접 옮기면 날아간다) |
| `OnAnimatorIK` 가 아예 안 불림 | 두 조건이 **둘 다** 필요하다: 컨트롤러 레이어의 **IK Pass 켜기** (`controller.layers` 는 복사본을 돌려주므로 **다시 대입**해야 반영된다), 그리고 스크립트가 **Animator 와 같은 GameObject** 에 있을 것 — 이 프로젝트는 Animator 가 액터 루트가 아니라 `Visual` 자식에 있다 |
| 첫 프레임에 총이 대포만 하게 번쩍임 | 씬에는 프리팹 원본 크기로 저장돼 있고 크기 보정이 Play 후에야 돌았다 → **씬 생성 시점에 한 번 굽는다**. 런타임 스폰(돌격대)은 **비활성 상태로 설정한 뒤 마지막에 켤 것** — 활성 오브젝트에 `AddComponent` 하면 필드를 넣기 전에 `Awake` 가 먼저 돈다 |
| 전원이 농땡이 모션 | `idle` 매칭 파일 3개를 사전순 정렬 → `CheckShoeIdle` 이 1등 |
| 캐릭터가 주저앉음 | Humanoid 애니메이터의 **빈 스테이트는 바인드 포즈가 아니라 머슬 0** |
| 250m에서 캐릭터가 단색 덩어리 | 256×1 팔레트 텍스처에 **mipmap ON** → 최하위 밉 = 전체 색 평균 |
| 팔레트 텍스처 수정이 되돌아감 | 에디터가 열린 채로 `.meta` 를 직접 고치면 Unity가 덮어씀. **반드시 메뉴로** |
| 소총이 손가락에 붙음 | 믹사모에 `RightHand` 와 `RightHandIndex1` 공존, 본 순서 미보장 → **이름 짧은 쪽 우선** |
| 몸통 히트박스가 팔 길이만큼 넓음 | 애니메이터 첫 프레임 전엔 T포즈 → `maxBodyWidthFraction` 으로 클램프 |
| ParticleSystem 오류 | `AddComponent<ParticleSystem>()` 는 즉시 재생 시작 → `duration` 설정 거부. `Stop()` 먼저 |
| **돌격대가 한꺼번에 코앞까지 밀려옴** | 각 병사가 "플레이어 반경 8~20m 링의 임의 점"으로 직진했다. 개체 AI를 아무리 똑똑하게 짜도 안 고쳐진다 — **접근 속도는 디렉터가 자리·허가·엄호사격으로 배급**해야 한다 |
| 엄폐 뒤에서 좌우로 덜덜 떪 | 몸 내밀 방향을 매 프레임 다시 계산 → 플레이어가 좌우로 움직이면 답이 뒤집힌다. **한 번 나올 때 한 번만** 정할 것 |
| 엄폐 판정이 항상 "시야 확보" | 조준점이 플레이어 **카메라**라 광선이 플레이어 캡슐에 먼저 맞는다. 사거리를 0.8m 짧게 쏘거나 플레이어 루트를 예외 처리할 것 |
| **탈출 헬기를 옥상 계층에 넣으면 NavMesh가 깨짐** | 베이크가 옥상 아래 모든 MeshFilter 를 걷기 가능 지면으로 수집한다 → 헬기가 도시 위에 떠 있는 섬으로 구워지고, 대기 위치가 덱에 구멍을 낸다. **씬 루트에 둘 것** |
| 헬기가 마젠타로 뜸 | 팩이 Built-in 셰이더 머티리얼 + URP 는 별도 `.unitypackage` 로 제공. `RC_MaterialUpgrade` 대상 폴더에 넣어 `에셋 — URP 머티리얼 변환` 으로 변환할 것 |
| 죽은 병사가 엄폐 자리를 계속 물고 있음 | `OnDestroy` 는 시체 소멸까지 안 온다. **사망 즉시** 자리를 반납해야 뒤에 대기하던 인원이 들어온다 |
| **몸을 내민 적을 쏴도 총알이 엄폐물에 맞음** | `peekOffset` 이 1.15m 고정인데 엄폐물이 2.4~5.0m 폭. **나와도 자기 엄폐물 뒤.** peek 은 반드시 **엄폐물 폭에서 계산**할 것 (4절) |
| 중앙 차선 적이 "보일 듯 말 듯" | 덕트 윗면(1.70)과 피킹 눈높이(0.85+0.85=1.70)가 **같은 높이**. 스치는 선은 판정이 랜덤하게 느껴진다 |
| 새 미션에서 스폰하자마자 하늘을 보고 있음 | 스폰 피치가 미션1 전용 상수 `6.7°` 였다. `RC_MapBuilder.SpawnPitch` 로 **계산**한다 |
| **표적 헬기가 헬리패드 NavMesh 에 구멍을 냄** | 탈출 헬기와 **같은 지뢰**. 베이크는 베뉴 트랜스폼 아래 모든 MeshFilter 를 지면으로 수집한다. 표적 헬기는 `MAP` 루트에 붙일 것 (베뉴 그룹의 형제) |
| 도로 미션 NavMesh 검증 실패 | 프로브가 `TerraceCenter`(=도로 한복판, y=0)였다. 걷는 면은 **연석 위 인도**다 → `map.targetSpawn` 을 프로브로 쓴다 |
| 세 계약의 표적이 전부 같은 얼굴 | 폴백이 `Pick(vipPrefabs, 0)` 였다. 사진을 책상에 올리기 전까지는 아무도 눈치채지 못한다 → `VipPrefabFor(mission, index)` |
| 사무실 핀보드 사진이 안 보임 | Unity `Quad` 의 법선은 **-Z**. 벽 쪽으로 180° 돌리면 사라지고, 보이더라도 사진이 좌우 반전된다 |
| **옥상 바닥이 지지직거림 (Z-fighting)** | 스카이라인 건물을 `PlaceScaledToHeight(..., NestHeight)` 로 놓으면 **팩 건물 지붕면과 덱 슬래브 윗면이 같은 y** 에 온다 → 위를 보는 면 두 개가 같은 깊이. 덱 아래로 `DeckClearance`(0.6m) 내려서 겹치지 않게 할 것. **덱 위에 얹힌 물건들(엄폐물·난간)의 바닥면이 덱 윗면과 같은 높이인 건 문제가 아니다** — 아래를 보는 면이라 백페이스 컬링된다 |
| **머리에 조준했는데 목에 맞음** | 250m 낙차 0.44m 는 머리 박스(0.43m) 하나 크기다. 배울 수 있는 오차가 아니라 **거짓말하는 조준점**이었다 → 계약의 **경사거리**(`√(거리²+고도차²)`)로 영점을 굽는다. 낙차 물리는 손대지 말고 **총열만 들 것** |
| **쏘면 표적이 화면 밖으로 사라짐** | 8배율 스코프 전체가 7.5° 인데 반동이 6.5° 였다 → 탄 비행 0.96초 중 0.65초 동안 표적이 안 보인다. **2.2° 로 내리고 잃은 타격감은 소총 모델**(`MountedRifleView`)로 옮길 것. 조준선을 떼지 않고 반동을 보여주는 유일한 방법 |
| 스코프 탄낙차 눈금이 아무 데도 안 맞음 | 눈금 간격이 **화면 반지름 기준**이라 배율마다 다른 홀드를 뜻했고 미터로는 아무 뜻도 없었다. 영점이 착탄점을 중앙에 올려 주므로 **사다리를 지우는 게 맞다** — 남겨 두면 낮게 조준하라고 유혹만 한다 |
| 조준점은 깨끗한데 탄이 난간에 박힘 | 탄 시작점을 **눈에 보이는 총구**(낮고 옆으로 치우침)로 잡으면 시선과 평행하게 나가 난간을 스친다. 게임 탄도는 **카메라 축에서** 출발시키고, 총구는 **트레이서 시작점**으로만 쓸 것 |
| 총알보다 경호대가 먼저 앎 | 경보를 `FirstShotFired`(발사)에 걸었다. 250m 면 탄이 0.96초를 난다 → **`FirstSniperImpact`(착탄)** 에 걸 것. 페이즈 전환은 발사 시점 그대로 두는 게 맞다 (타이머는 쏜 순간부터) |
| 소총이 카메라를 따라 허공에서 흔들림 | 카메라의 자식으로 두면 난간에 거치된 게 아니라 들고 있는 그림이 된다 → **월드에 고정**하고 **삼각대가 짚은 점을 축으로** 회전시킨 뒤 삼각대를 역보정할 것 (`MountedRifleView`) |
| 웹 빌드에서 한글이 □□□ | 웹은 **OS 설치 폰트로 폴백이 안 된다** → 폰트를 `Resources/` 에 번들하고 모든 IMGUI 스타일이 그걸 명시적으로 쓸 것 (`UIFontProvider`) |
| 웹에서 스코프 중앙점이 찌그러짐 | IMGUI 사각형 3개로 원을 근사했는데 **분수 픽셀 반올림**이 브라우저 해상도마다 다르게 떨어졌다 → 안티에일리어싱된 텍스처 한 장으로 그릴 것 |
| **씬을 안 고쳤는데 AI 가 이상함** | 씬 YAML 이 **옛 어셈블리로 구워지면** 그 뒤 추가된 public 필드가 아예 직렬화되지 않고 C# 기본값으로 로드된다 (`escortWhileCalm` 이 조용히 false). 인스펙터에 필드가 보인다고 값이 저장돼 있다는 뜻이 아니다 → **★ 재생성**, 급하면 `씬 — 메커니즘 필드만 채우기` |

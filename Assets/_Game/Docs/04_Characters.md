# 내 매지카복셀 캐릭터 넣기

> 갱신: 2026-09-03. 납품 스펙(모델링 단계에서 지켜야 할 것)은 `05_CharacterSpec.md`,
> 전체 빌드 절차는 `00_HANDOFF.md` 2·5절.

캐릭터는 코드에 하드코딩돼 있지 않습니다. **배역은 폴더명이 정하고**,
세부 보정은 `Assets/_Game/CastingConfig.asset` 하나가 갖고 있습니다.

---

## 순서

### 1) 캐릭터를 폴더에 넣는다 — **폴더명이 배역입니다**

```
Assets/VoxelCharacter/
  Vip1/  Vip2/  Vip3/     VIP 3종 (계약당 1명)
  Guard1/  Guard2/        경호원 2종 (섞여서 배치)
  Assault/                돌격대
  Player/                 ← 1인칭이라 미사용
  _Animations/            공용 클립 폴더 (비어 있어도 인식됨)
```

`RC_AutoCast` 가 **폴더명을 보고** 배역을 배정합니다. 아무 폴더에나 넣으면 안 됩니다.

### 2) 리그를 Humanoid로 변환한다

```
Rooftop Contract ▸ 도구 ▸ 캐릭터 — 리그 Humanoid 변환
```

FBX를 전부 재임포트하므로 느립니다. **캐릭터를 추가·수정했을 때만** 돌리면 됩니다
(그래서 `★ BUILD EVERYTHING` 에 들어 있지 않은 유일한 단계입니다).

### 3) 히트박스를 눈으로 확인한다

Project 창에서 캐릭터를 선택하고:

```
Rooftop Contract ▸ 도구 ▸ 캐릭터 — 히트박스 미리보기
```

씬에 미리보기 오브젝트가 생기고 **빨간 박스 = 머리 / 파란 박스 = 몸통**이 그려집니다.
콘솔에 실측 키와 어떤 앵커가 잡혔는지도 찍힙니다.

**박스가 안 맞으면** `CastingConfig` 의 `headHeightFraction` 만 조정하면 됩니다.

| 캐릭터 비율 | 권장값 |
|---|---|
| 치비 / 머리 큰 복셀 (머리가 키의 1/3) | **0.30 ~ 0.38** |
| 표준 복셀 인체 | **0.22 ~ 0.26** (기본 **0.24**) |
| 사실적 8등신 | **0.13 ~ 0.16** |

확인이 끝나면 미리보기 오브젝트는 그냥 지우면 됩니다.

### 4) 배역을 확인한다 (자동 배정으로 부족할 때만)

```
Rooftop Contract ▸ 도구 ▸ 캐릭터 — 배역 자동 배정      ← 폴더명으로 빈 슬롯만 채움
Rooftop Contract ▸ 캐스팅 설정 (CastingConfig)         ← 손으로 지정하고 싶을 때
```

자동 배정은 **비어 있는 배역만** 채웁니다. 손으로 지정한 배역은 절대 건드리지 않습니다.

### 5) 전체를 다시 짓는다

```
Rooftop Contract ▸ ★ BUILD EVERYTHING (전체 재생성)
```

팔레트 텍스처 수정 · 배역 배정 · 씬 4개 생성 · NavMesh 베이크가 한 번에 돕니다.

> **표준 순서**: `리그 Humanoid 변환` → `★ BUILD EVERYTHING`. 그 외엔 ★ 하나면 됩니다.

---

## 무기가 손에 안 맞을 때

자동 계산은 총을 손 *근처*까지만 가져다 놓습니다. 몸통이 짧은 복셀 캐릭터에 0.6~0.9m 총을
쥐여 주면 **기하학적으로 안 겹치는 답이 아예 없어서**, 마지막 몇 cm는 사람 눈이 정해야 합니다.

```
Rooftop Contract ▸ 도구 ▸ 무기 — 그립 워크벤치 (SMG_P)   ← 대상 무기별로 메뉴가 따로 있음
                            → 씬 뷰에서 Weapon 을 맞춤
                   도구 ▸ 무기 — 포즈 순환               ← 걷기·달리기에서도 확인
                   도구 ▸ 무기 — 그립 저장               ← CastingConfig 에 기록
                   ★ BUILD EVERYTHING
```

워크벤치는 무기마다 따로입니다 (`SMG_P` / `AR_U` / `Pistol_H` / `Pistol_I`).
형상이 달라서 **같은 그립 값이나 왼손 IK 캡처값을 공유할 수 없습니다** — 자세한 건 `06_WeaponLoadout.md`.

> `그립 저장` 은 오른손 그립뿐 아니라 **왼손 IK 목표까지 같이 캡처**합니다.
> 총은 오른손에 붙으므로 왼손은 항상 거짓말이고, `WeaponSupportIK` 가 그걸 총열로 끌어옵니다.

## 히트박스가 잡히는 원리

머리 앵커는 **명시적인 것부터** 순서대로 찾습니다:

| 순위 | 방법 | 언제 쓰이나 |
|---|---|---|
| 1 | `ActorSetup.headAnchorOverride` 인스펙터 지정 | 수동 확정 |
| 2 | **`HITBOX_HEAD` 라는 이름의 자식 오브젝트** | 리그가 없어도 확실하게 잡고 싶을 때 |
| 3 | **Humanoid 아바타 본** (`HumanBodyBones.Head`) | ✅ **지금 캐릭터들은 여기서 잡힙니다** |
| 4 | 이름에 `head` / `skull` / `neck` 이 들어간 본 | Generic으로 임포트했을 때 |
| 5 | 메시 실루엣 상단 `headHeightFraction` | 자동 폴백, 항상 동작 |

2번을 쓰고 싶으면 씬에 캐릭터를 올려놓고:
```
Rooftop Contract ▸ 도구 ▸ 캐릭터 — 히트박스 마커 생성
```
`HITBOX_HEAD` 와 `ATTACH_WEAPON` 두 개가 생깁니다. 머리 중앙과 오른손 위치로 옮기고
프리팹으로 저장하면 끝입니다.

### 박스가 캡슐이 아닌 이유
복셀 캐릭터는 박스입니다. 실제 **메시 정점을 전부 읽어** 머리 영역과 몸통 영역의 AABB를
각각 딱 맞게 잡습니다. 캡슐로 비율을 추정하는 것보다 정확하고 아트와도 어긋나지 않습니다.
스킨드 메시는 `BakeMesh` 로 현재 포즈를 떠서 측정하므로 리깅 여부와 무관하게 같은 결과가 나옵니다.

> ⚠️ **`Renderer.bounds` 로 재면 안 됩니다** — 스킨드 메시에서 약 11% 패딩된 값이 나옵니다.
> 그리고 `BakeMesh` 출력에는 계층 스케일이 **이미 포함**돼 있어서 `localToWorldMatrix` 를
> 또 곱하면 제곱이 됩니다. 코드는 두 행렬 후보를 `renderer.bounds` 와 대조해 자동 선택합니다.

## 임포트 보정 (`CastingConfig`)

매지카복셀 익스포트에서 거의 항상 걸리는 것들:

| 필드 | 문제 | 처리 |
|---|---|---|
| `normalizeHeight` + `targetHeight` | **1복셀 = 1유닛**이라 키가 30배쯤 나옴 | 켜두면 **1.8m**로 자동 정규화 |
| `groundPivot` | 피벗이 발밑이 아니라 모델 중심 | 켜두면 발바닥을 바닥에 붙임 |
| `modelYawOffset` | 모델이 +Z를 안 봄 | 90 단위로 돌려가며 맞춤 |
| `headHeightFraction` | 머리 박스 크기 | 위 표 참조 |
| `maxBodyWidthFraction` | T포즈에서 몸통 박스가 **양팔 길이만큼** 벌어짐 | 기본 0.5 (키의 절반)로 클램프 |
| `weaponHandOffset` / `weaponHandEuler` | 손뼈 기준 총 위치·각도 | **워크벤치로 맞춰 저장** |
| `weaponGripManual` | 켜지면 자동 계산을 끔 | `그립 저장` 이 자동으로 켬 |

정규화는 **에디터 빌드 시점**에 적용됩니다. 런타임 스케일 조정이 아니라 씬에 확정 값으로
박히므로, NavMeshAgent 크기·히트박스·무기 오프셋이 전부 같은 기준(1.8m)으로 맞습니다.

> ⚠️ **무기 크기도 같은 시점에 굽습니다.** 손뼈가 캐릭터 정규화 스케일(약 1.53배)을 갖고 있어서
> 무기가 그걸 상속하면 사람보다 큰 총이 됩니다. 런타임 스폰(돌격대)은
> **비활성 상태로 설정한 뒤 마지막에 켜야** 합니다 — 활성 오브젝트에 `AddComponent` 하면
> 필드를 넣기 전에 `Awake` 가 먼저 돕니다.

## 애니메이션 — 파일명으로 찾습니다

믹사모가 클립을 캐릭터 이름으로 저장하기 때문에 **클립 이름이 아니라 파일명**을 봅니다
(`Guard2Idle.fbx` 안의 클립명은 `Guard2`).

| 키워드 | 용도 |
|---|---|
| `lookaround` | **무장 액터(경호원·돌격대)의 기본 대기.** 소총을 든 자세라 총이 놓일 자리가 있음 |
| `idle` | 대기 (Humanoid는 **필수** — 없으면 주저앉음). VIP·민간인의 기본 |
| `walk` / `run` | 이동 |
| `checkshoe` | 농땡이 idle (경호원 **한 명만**, 35% 확률) |
| `headshotdeath` / `bodyshotdeath` / `death` | 사망 (헤드샷/보디샷 구분) |
| `terrified` | VIP 대피 직전 연출 |
| `RifleShootingplay` / `pistolShooting` | 사격 |

**탐색 순서**: 본인 폴더 → `_Animations` → 다른 캐스팅 폴더
**같은 키워드에 여러 파일이 걸리면 → 파일명이 가장 짧은 것** (수식어 없는 게 "그냥 idle")
**역할 태그**: 파일명에 `vip` 가 있으면 VIP 전용 (`VIPRunning` vs `Guard1RifleRun` 구분)

> **`lookaround` 와 `checkshoe` 는 무장 역할에만 배정됩니다.** 둘 다 소총을 든 채로 만들어진
> 클립이라 VIP나 민간인에게 붙으면 **없는 총을 들고 흉내내는 그림**이 됩니다.

> **무장 액터의 기본 idle이 `lookaround` 인 이유**: 차렷 자세(`Guard1Idle`)는 팔이 몸통에 붙어
> 있어서 **총이 놓일 자리가 아예 없습니다.** 오프셋으로 고칠 수 있는 문제가 아니라 자세의 문제였습니다.

**컨트롤러는 생성기가 만듭니다** — `Assets/_Game/Animation/RC_*.controller` 6개
(`RC_Vip1~3`, `RC_Guard1~2`, `RC_Assault`)는 **생성 산출물**이라 손으로 편집하면 다음 빌드에
날아갑니다. 고칠 곳은 `RC_SceneBuilder` 의 컨트롤러 조립 코드입니다.

> 클립이 하나도 없어도 게임 로직은 전부 정상 동작합니다 — 사망은 클립이 없으면 절차적 전도로
> 대체되고, `Speed` 를 쓰는 코드는 전부 null 체크가 걸려 있습니다.
> 다만 **Humanoid에 idle이 없으면 주저앉습니다** (빈 스테이트는 바인드 포즈가 아니라 머슬 0).

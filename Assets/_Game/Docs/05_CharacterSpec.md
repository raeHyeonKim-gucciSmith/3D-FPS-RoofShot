# 캐릭터 납품 스펙 (매지카복셀 → 믹사모 → Unity)

믹사모를 쓰실 거라면 **믹사모 오토리거의 요구사항이 모든 것을 결정한다.**
히트박스·배치 쪽은 이미 자동 보정이 들어가 있어서 사실상 제약이 거의 없다.

---

## 1. 결론부터

| 항목 | 값 |
|---|---|
| **포맷** | **`.fbx`** (OBJ 아님) |
| 메시 | **단일 메시 1개**로 병합 |
| 포즈 | **A포즈** (팔 45°). T포즈도 됨 |
| **팔·다리** | **몸통과 떨어져 있어야 함 ← 가장 중요** |
| 방향 | **+Z 정면**, Y-up |
| 피벗 | **양발 사이 바닥** (0,0,0) |
| 크기 | 아무거나 (자동 정규화). 굳이 맞추면 1.8m |
| 텍스처 | 팔레트 PNG 동봉 |
| 폴리곤 | 2만 tri 이하 권장 |
| 필요 개수 | **현재 6종이 들어와 있음** — VIP 3 (계약당 1명) · 경호원 2 · 돌격대 1. 민간인은 기존 복셀에서 재사용 중 |

> 갱신: 2026-09-03. **VIP는 계약마다 다른 인물이라 3종이 필요합니다** — 사무실 계약 보드가
> 세 사람의 얼굴을 **동시에** 보여주기 때문에, 하나로 돌려 쓰면 셋이 같은 얼굴로 나옵니다.
> (실제로 그랬고, 사진을 책상에 올리기 전까지 아무도 눈치채지 못했습니다.)

**넣을 위치**: `Assets/VoxelCharacter/<역할이름>/` — **폴더명이 배역을 결정합니다**
(`Vip1` `Vip2` `Vip3` `Guard1` `Guard2` `Assault`). 자세한 건 `04_Characters.md`.

## 2. 왜 이 스펙인가

### `.fbx` — OBJ가 아닌 이유
OBJ는 리그를 담지 못한다. 믹사모를 거치면 결과물이 어차피 FBX이므로,
처음부터 FBX로 통일하면 **임포트 설정을 한 번만 잡으면 된다.**
지금 단계(리그 없음)에서도 FBX는 문제없이 동작한다 — 히트박스는 메시 정점에서 측정하므로 리그가 필요 없다.

### 단일 메시
믹사모 오토리거는 **메시가 하나일 때만** 안정적으로 스키닝한다.
부위별로 쪼갠 모델은 리깅 단계에서 탈락한다.
(앞서 "부위별 분리"도 지원한다고 했지만, 그건 믹사모를 안 쓸 때의 얘기다.)

### 팔·다리가 몸통에서 떨어져 있을 것 ← **가장 흔한 실패 원인**
매지카복셀에서 캐릭터를 만들면 팔이 몸통에 **딱 붙거나 파고들어 있는** 경우가 대부분이다.
이 상태로 업로드하면 오토리거가 팔과 몸통을 하나의 덩어리로 인식해서
**웨이트가 뭉개지거나 리깅 자체가 실패한다.**

→ 겨드랑이·사타구니에 **최소 1~2복셀의 빈 공간**을 두고 모델링할 것.
이것만 지키면 오토리깅 성공률이 확 올라간다.

### A포즈 / +Z 정면 / 발밑 피벗
- 오토리거가 관절 마커를 자동 배치할 때 기준이 되는 자세다.
- 방향과 피벗은 **틀려도 자동 보정된다** (`modelYawOffset`, `groundPivot`).
  다만 맞춰 오면 설정을 건드릴 일이 없어진다.

### 크기는 신경 안 써도 됨
매지카복셀은 1복셀 = 1유닛이라 키가 30~40 유닛으로 나오는데,
`CastingConfig.normalizeHeight` 가 빌드 시점에 1.8m로 맞춘다.
NavMeshAgent 크기·히트박스·무기 위치가 전부 이 값 기준으로 정렬된다.

## 3. 믹사모 → Unity 임포트

### 다운로드
- **베이스 캐릭터 1개**: `FBX for Unity` + **With Skin**
- **애니메이션들**: `FBX for Unity` + **Without Skin** (파일이 훨씬 가볍다)

### Unity 임포트 설정
| 설정 | 값 | 이유 |
|---|---|---|
| Rig ▸ Animation Type | **Humanoid** | 여러 믹사모 클립을 리타겟팅해서 돌려쓸 수 있다 |
| Rig ▸ Avatar Definition | 베이스: `Create From This Model` / 애니메이션: `Copy From Other Avatar` | |
| **Rig ▸ Optimize Game Objects** | **반드시 끌 것** ⚠️ | 켜면 본 트랜스폼이 계층에서 사라져 **무기 부착과 머리 앵커가 전부 깨진다** |
| 텍스처 ▸ Filter Mode | **Point (no filter)** | 안 그러면 복셀 색이 서로 번진다 |
| 텍스처 ▸ Compression | **None** | 팔레트 텍스처는 압축하면 색이 뭉개진다 |

> `Optimize Game Objects` 를 꼭 켜야 한다면, 같은 화면의
> **Extra Transforms to Expose** 에 `Head` 와 `RightHand` 두 개를 추가하면 된다.

머티리얼이 분홍색으로 나오면 셰이더를 `Universal Render Pipeline/Lit` 으로,
Base Map 에 팔레트 PNG를 물려주면 끝난다.

## 4. 이번에 추가한 믹사모 대응

코드 쪽에 세 가지를 미리 넣어뒀다.

**① Humanoid 아바타를 직접 물어본다**
휴머노이드로 임포트했으면 `Animator.GetBoneTransform(HumanBodyBones.Head / RightHand)` 로
본을 바로 가져온다. 이름 추측이 필요 없어 가장 정확하다.

**② 본 이름은 "가장 짧은 매칭"을 고른다**
믹사모 리그에는 `mixamorig:RightHand` 와 `mixamorig:RightHandIndex1` 이 함께 있다.
본 순서가 보장되지 않아서, 먼저 찾은 것을 쓰면 **소총이 손가락 마디에 붙는** 일이 생긴다.
이름이 짧은 쪽을 고르도록 바꿨다.

**③ 몸통 히트박스 가로 폭에 상한을 걸었다**
리깅된 캐릭터는 애니메이터가 첫 프레임을 재생하기 전까지 **바인드 포즈(T포즈)** 로 서 있다.
그대로 재면 몸통 박스가 **양팔 길이만큼** 벌어져서, 캐릭터 옆 1m를 쏴도 맞는 상태가 된다.
`maxBodyWidthFraction` (기본 0.5 = 키의 절반)으로 몸통 축 기준으로 잘라낸다.

## 6. 권장 진행 순서

1. 캐릭터 **1종만** 먼저 완성해서 넣는다
2. `Rooftop Contract ▸ 도구 ▸ 캐릭터 — 히트박스 미리보기` 로 박스 확인 → `headHeightFraction` 확정
3. 그 1종을 믹사모에 태워서 리깅이 되는지 확인 (팔 간격 문제를 여기서 잡는다)
4. Unity 임포트 설정 확정
5. **그 다음에 나머지를 몰아서 만든다**

1종으로 파이프라인을 뚫어놓고 나머지를 찍어내는 게, 다 만들고 나서
"팔이 붙어 있어서 리깅이 안 된다"를 발견하는 것보다 압도적으로 싸다.

## 7. 애니메이션 (믹사모에서 받을 것)

**클립은 파일명으로 찾는다.** 믹사모가 클립을 캐릭터 이름으로 저장하기 때문이다
(`Guard2Idle.fbx` 안의 클립명은 `Guard2`). 그러니 **파일명에 아래 키워드가 들어가게** 저장할 것.

| 파일명 키워드 | 믹사모 클립 예시 | 누가 쓰나 | 필수 여부 |
|---|---|---|---|
| `idle` | `Standing Idle` | VIP · 민간인 | **필수** — Humanoid는 없으면 주저앉는다 |
| `lookaround` | `Look Around` (소총 파지) | **무장 액터의 기본 대기** | **필수급** — 차렷 자세엔 총이 놓일 자리가 없다 |
| `walk` | `Walking` | 전원 | **필수급** |
| `run` | `Running` | 돌격대 · 대피하는 VIP | 권장 |
| `checkshoe` | 아무 농땡이 idle | 경호원 **한 명만** (35%) | 선택 |
| `headshotdeath` / `bodyshotdeath` / `death` | `Headshot Death` 등 | 전원 | 선택 — 없으면 절차적 전도 |
| `terrified` | `Terrified` | VIP (대피 직전) | 선택 |
| `RifleShootingplay` / `pistolShooting` | `Firing Rifle` / `Pistol Idle` | 사격 연출 | 선택 |

**탐색 순서**: 본인 폴더 → `_Animations` → 다른 캐스팅 폴더
**같은 키워드에 여러 파일이 걸리면 → 파일명이 가장 짧은 것**
(수식어 없는 게 "그냥 idle". 예전에 `CheckShoeIdle` 이 사전순 1등이라 **전원이 농땡이 모션**이었다.)
**역할 태그**: 파일명에 `vip` 가 있으면 VIP 전용으로만 배정된다.

> `lookaround` 와 `checkshoe` 는 **무장 역할에만** 배정된다. 둘 다 소총을 든 채로 만들어진
> 클립이라 VIP나 민간인에게 붙으면 없는 총을 들고 흉내내는 그림이 된다.

**컨트롤러는 손으로 만들지 않는다.** `Assets/_Game/Animation/RC_*.controller` 6개
(`RC_Vip1~3` · `RC_Guard1~2` · `RC_Assault`)는 **생성기가 만드는 산출물**이라, 손으로 편집하면
다음 빌드에 날아간다. 클립을 폴더에 넣고 `★ BUILD EVERYTHING` 을 누르면 알아서 물린다.

애니메이션이 아예 없어도 게임 로직은 전부 정상 동작한다 (`idle` 만 예외).
